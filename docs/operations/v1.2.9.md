# v1.2.9 implementation

Theme: **Finish the stack you already show.** Product context: [Roadmap](/roadmap).

Do not start Viewer/family Glance, unified item glance, PWA, or new *arr apps in this slice. rTorrent stays unimplemented (integrations already use `slug: null`).

## Success criteria

- Transmission, Deluge, and NZBGet queues appear on Downloads with add, pause, and remove (parity with qBittorrent / SABnzbd).
- Owners and admins can stop a live session and send a Jellyfin on-screen message; cards explain transcode reasons.
- Home can alert when concurrent streams or transcodes exceed configured caps.
- `/timeline` is in the main nav; Calendar is hidden until Sonarr, Radarr, or Lidarr is connected.
- SickChill copy does not claim Arr calendar sync.
- Settings → Webhooks can create, test, and deliver **ntfy** targets.

### Adapter notes

**Transmission** (RPC 1.7+):

- `POST {url}/transmission/rpc` with session-id retry on HTTP 409 (`X-Transmission-Session-Id`).
- Auth: HTTP basic from `values.username` + `values.secret`.
- Methods: `torrent-get` (fields: `id`, `hashString`, `name`, `status`, `percentDone`, `downloadedEver`, `sizeWhenDone`, `rateDownload`, `rateUpload`, `addedDate`, `labels`/`downloadDir` for Arr category), `torrent-add` (`filename` for magnet/URL), `torrent-stop` / `torrent-start`, `torrent-remove` (`delete-local-data` when `deleteFiles`).
- Store `hash` and numeric `torrentId` on the queue item.

**Deluge** (WebUI JSON-RPC):

- `POST {url}/json` with cookie session. Login: `auth.login` with `values.secret` (password).
- Queue: `web.update_ui` or `core.get_torrents_status` for `name`, `progress`, `total_wanted`, `total_done`, `download_payload_rate`, `upload_payload_rate`, `paused`, `state`, `time_added`.
- Add: `core.add_torrent_magnet` / `core.add_torrent_url`. Pause: `core.pause_torrent` / `core.resume_torrent`. Remove: `core.remove_torrent`.
- Item `id`: `{instanceId}-{torrent_id}` (40-char hash).

**NZBGet** (JSON-RPC):

- `POST {url}/jsonrpc` with HTTP basic (`values.username` if present, `values.secret` as password or API-style secret already stored).
- Queue: `listgroups`. Map `NZBName`, `Status`, `FileSizeMB`, `RemainingSizeMB`, `DownloadRate`, `NZBID`.
- Add: `append` with NZB URL. Pause/resume: `editqueue` `GroupPause` / `GroupResume`. Delete: `GroupDelete` / `GroupFinalDelete` when `deleteFiles`.
- Item field `nzbId` analogous to `nzoId`.

**IDs for pause/remove:** extend `findClient` + hash helpers the same way `torrentHash` / `nzoId` work today so stored items survive a sync.

| File | Change |

Reuse the existing `Authorization: MediaBrowser Token=...` headers. |
| `apps/api/routes/api.js` (or a small `routes/sessions.js` mounted from `server.js` if you want to avoid growing the monolith) | `POST /api/sessions/stop` `{ sessionId }`. `POST /api/sessions/message` `{ sessionId, header, text, timeoutMs }`. | `apps/web/src/pages/components/sessions/sessions.jsx` | Pass role/kiosk flags if the card cannot read them from the JWT itself. |
